# Experiment: Shared call and conditional scheduling costs

- Date: 2026-09-11
- Baseline: `b45bdbf`, whose runtime is unchanged from `7f84553`;
  executable `build/perf/call-path/baseline/toy`
- Candidates: four independent patches against that runtime, archived below;
  **none retained in the interpreter**
- OS / CPU: Linux 7.2.3-arch1-3, Intel Core i9-11900K, 8 cores / 16 threads
- Power state: `powersave` governor, turbo enabled; no affinity or priority
  changes; no builds or other benchmark processes overlapped timed comparisons
- Primary compiler: GCC 16.2.1 20260810, Nob Release, `-O3 -DNDEBUG`, no LTO
- Cross-check: GCC 15.3.0, independently compiled baseline and conditional
  candidate with the same optimization flags, no LTO
- Timing: fresh-process wall time, alternating baseline/candidate order, one
  discarded warmup per executable/workload; fixed phase order inside processes

## Outcome

The first follow-up to the cross-language comparison did **not** produce a
runtime change worth keeping. Three call-path prototypes were essentially
neutral outside a tight user-word loop. A fourth reduced conditional scheduling
work and improved isolated branch loops under both compilers, but its small
application gains did not generalize reliably across runs and compiler builds.

The retained work is a checked diagnostic workload and paired runner, expanded
conditional regression coverage, and this evidence. Runtime source is restored
to the baseline. The rejected patches are research artifacts, not supported
build variants or fully validated production changes.

## Controlled workload

[`call-path.toy`](../call-path.toy) checks ten cases: inline increment, user-word
increment, quotation `exec`, symbol `exec`, boolean and quotation-predicate
branches, three Fibonacci(28) variants, and a fold. Each phase reports its own
monotonic wall time and checksum. The runner independently validates all cases,
checksums, and positive timings before accepting a sample.

The ordinary Fibonacci word and `binrec` are close in this workload. In the
GCC 16 conditional screening run, their baseline phase medians were 80.607 and
84.104 ms. The ordinary word with a quotation predicate took 150.893 ms.
This does not establish that `binrec` is intrinsically slow: predicate sandboxing,
ambient stack depth, frames, and continuation structure differ between these
idioms. Their common naive Fibonacci algorithm is intentionally diagnostic,
not a recommendation for implementing Fibonacci in Toy.

## Independent prototypes

Ratios are median paired candidate/baseline elapsed time; below 1 is faster.
The process column includes every phase and is not an application score.

| Prototype | Pairs | User-word loop | Predicate branch | Diagnostic process |
| --- | ---: | ---: | ---: | ---: |
| Share frame/program ownership with the execution sidecar | 5 | 0.9605 | 1.0503 | 0.9925 |
| Inline primary-way quotation-cache acquisition | 5 | 0.9575 | 1.0114 | 0.9931 |
| Keep prepared execution metadata on user words | 5 | 0.9333 | 1.0347 | 0.9997 |
| Directly schedule initial conditional vectors | 7 | 1.0073 | 0.9335 | 0.9842 |

1. **Shared ownership:** frames retain their sidecar instead of also retaining
   the program already owned by that sidecar. The mixed phase results did not
   justify changing this ownership boundary.
   [Patch](2026-09-11-call-path/shared-owner.patch),
   [raw samples](2026-09-11-call-path/shared-owner-calls.json).
2. **Cache acquisition:** split the primary cache hit from the out-of-line
   associative lookup/allocation path. This did not yield a clear overall win.
   [Patch](2026-09-11-call-path/cache-fast.patch),
   [raw samples](2026-09-11-call-path/cache-fast-calls.json).
3. **Prepared words:** let each invoked user definition retain its execution
   metadata and bypass the quotation-cache search on later calls. This adds a
   pointer to dictionary entries and pins metadata until replacement, clearing,
   or teardown. The user-word loop improved about 6.7%, but five application
   pairs gave ratios of 1.0209 for JSON, 1.0222 for graph search, 1.0124 for log
   reporting, and 1.0104 for particles. There is no application benefit here to
   pay for the added state and lifetime rules.
   [Patch](2026-09-11-call-path/prepared-user.patch),
   [phase samples](2026-09-11-call-path/prepared-user-calls.json),
   [application pairs](2026-09-11-call-path/prepared-user-applications.txt).
4. **Conditional scheduling:** `if`/`ifelse` constructors push the existing
   native continuation and directly schedule an initial vector predicate or
   boolean-selected vector branch. Symbols retain normal iterative dispatch;
   debug hooks, pending deferred calls, and interruption force the original
   path. No frames, scopes, snapshots, or input references are removed.
   [Patch](2026-09-11-call-path/conditional.patch),
   [phase samples](2026-09-11-call-path/conditional-calls.json).

All rows compare against the original baseline, not the preceding prototype.
The first two were rejected during screening; they were not tested against the
full application suite. These small sample sets are hypothesis screens, not
precise estimates of one-percent effects.

## Conditional cross-checks

The most promising screen was followed by a nine-pair sweep of all 18 Toy
benchmarks, eleven phase-aware application pairs, and a second GCC build.

| Workload | GCC 16 full-sweep ratio | GCC 15 ratio |
| --- | ---: | ---: |
| JSON | 1.0003 | 0.9923 |
| Graph search | 1.0120 | 0.9956 |
| Log report | 1.0115 | 1.0132 |
| Particles | 0.9669 | 0.9969 |
| Runtime internals | 1.0010 | 0.9943 |
| Dispatch | 1.0099 | 1.0069 |

[Full GCC 16 pairs](2026-09-11-call-path/gcc16.txt),
[GCC 15 pairs](2026-09-11-call-path/gcc15.txt). Most controls remain near neutral;
small positive or negative ratios should not be called resolved changes.
The GCC 15 executables also use a different link ordering from Nob, providing
a compiler/code-placement cross-check, not an isolated test of compiler version.

The initial seven-pair application screen suggested 2.05% less JSON time and
2.87% less particle time. JSON's gain disappeared in the full sweep. The
eleven-pair phase check supported roughly 2–3% less particle advancement time
across population/timestep scaling, but that gain did not repeat in the GCC 15
process comparison. Log application phases ranged from near neutral to about
3.5% faster; its process results varied in sign across comparisons.
[Initial screen](2026-09-11-call-path/conditional-screen.txt),
[all application-phase samples](2026-09-11-call-path/application-phases.json).

The tight branch effects did repeat: boolean branches had ratios 0.9418 (GCC 16)
and 0.9542 (GCC 15); predicate branches had 0.9335 and 0.9357. Ordinary Fibonacci
was about 3% faster under both compilers, while quotation-predicate Fibonacci
remained near neutral.
[GCC 15 phase samples](2026-09-11-call-path/gcc15-calls.json).

A seven-pair baseline-versus-itself control had a process ratio of 0.9966 and
phase ratios from 0.9876 to 1.0076. Individual pairs in the wider sweep include
larger scheduling/frequency outliers. The paired medians reduce drift; they do
not eliminate noise or compiler/code-layout sensitivity.
[Self-comparison](2026-09-11-call-path/self-calls.json).

## Attribution and semantic constraints

The conditional prototype changes only one Observe counter:

| Workload | Baseline continuation steps | Candidate steps | Reduction |
| --- | ---: | ---: | ---: |
| JSON | 6,195,151 | 4,882,531 | 1,312,620 (21.2%) |
| Particles | 2,432,443 | 1,748,918 | 683,525 (28.1%) |

All instruction, call, frame, stack high-water, cache, and dispatch counters
remain equal. [JSON before](2026-09-11-call-path/json-before.json) /
[after](2026-09-11-call-path/json-after.json),
[particles before](2026-09-11-call-path/particles-before.json) /
[after](2026-09-11-call-path/particles-after.json).
Scheduling work moved into the constructor; only a VM dispatch hop disappeared.
A 21% reduction in this counter is emphatically not a 21% reduction in runtime
work or elapsed time. GCC 16 executable `.text` grew by only 256 bytes, from
316,851 to 317,107, but small code-placement changes can still affect timing.

The experiment also motivated regressions for normal/debug frame parity,
dynamic shadowing, predicate stack isolation, scratch-backed snapshots, error
recovery, queued events before predicate snapshots, interruption, symbolic
combinator chains, and unchosen-quotation resource lifetime. These tests remain
useful with the unchanged runtime. The conditional prototype passed focused
Release and Observe checks, including an experimental assertion that exactly
two initial steps disappeared without removing any frames. It was not promoted
to a fully validated release candidate.

  wall-bounce, and energy checks pass.

avoid unrelated REPL history writes. The retained changes do not alter runtime
execution or capture behavior. The focused prototype checks above should not
be confused with this full validation of the restored runtime and new tests.

## Reproduction and next experiment

```console
python3 benchmarks/measure-call-path.py \
  --baseline build/perf/call-path/baseline/toy \
  --toy build/perf/call-path/eager-if/toy --runs 7 --output build/calls.json
nob benchmark --compare BASELINE CANDIDATE --runs 9 --warmup 1
python3 benchmarks/measure-applications.py \
  --baseline BASELINE --toy CANDIDATE --runs 11 --json
```

Raw phase records include executable and diagnostic-source SHA-256 hashes.
Saved executables are local build artifacts, not repository dependencies. To
rebuild a rejected variant, apply its runtime-only patch to `b45bdbf`; the newly
added diagnostic source can be used with either build. GCC 15 was built with:

```console
gcc-15 -std=c11 -Wall -Wextra -Wpedantic -Iinclude -Isrc -Ideps/linenoise \
  -DTOY_SHARED_SUFFIX='".so"' -D_POSIX_C_SOURCE=200809L -O3 -DNDEBUG \
  src/*.c src/generated/tf_docs.c src/cli/*.c deps/linenoise/linenoise.c \
  -o OUTPUT -lm -ldl
```

Supply a sibling `core` directory or an explicit `--core-path` for application
imports. Both sides must use the same core packages and workload sources.

The next candidate should remove shared work rather than only reroute calls:
measure predicate snapshot/refcount traffic and temporary boolean allocations,
then evaluate value representation separately. Neither these screens nor the
cross-language Fibonacci gap establishes the attainable gain. Keep the
application/compiler checks as the acceptance gate.
